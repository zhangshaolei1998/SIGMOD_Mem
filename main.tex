\begin{abstract}
Large Language Model (LLM) agents accumulate interaction histories that grow to hundreds of thousands of tokens per user, yet current memory systems store this data but do not manage it: every question, whether a simple fact lookup or a count across multiple records, is served by the same retrieval pipeline. This leads to two limitations: the system fails systematically on complex queries that require aggregation or comparison, and it wastes LLM calls on easy queries that do not need them while never learning which memories are useful. We introduce \sys{}, a memory management system for LLM agents that addresses three challenges of managing agent memory. (i)~\textbf{Architecture.} \sys{} organizes sessions into a typed catalog, routes each query to one of three patterns (point lookup, aggregation, or comparison) using keywords alone, and dispatches it to a specialized operator, with no LLM call needed for routing. (ii)~\textbf{Performance.} A \emph{Second-Order Memory} logs which catalog entries contribute to correct answers for each user and promotes useful entries in subsequent queries, forming a workload feedback loop that improves accuracy over time. (iii)~\textbf{Efficiency.} A \emph{Cost-Aware Executor} assigns different LLM call budgets to different query patterns and stops early when two samples agree. Across eight long-term memory benchmarks, \sys{} matches or improves the strongest prior memory system on every one, by an average of $2.6$ points and by up to $5.6$ points on \lmes{}. On \membench{} it further reduces LLM calls by $50.7\%$ relative to a Uniform-$K{=}3$ reference while attaining higher accuracy.
\end{abstract}
