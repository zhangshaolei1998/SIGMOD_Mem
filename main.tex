\begin{abstract}
LLM agents use persistent memory to recover user information from past
conversations. Existing systems manage stored content but provide limited
support for learning from agent--memory interactions: memory queries,
returned facts, the agent's reported use, and execution outcomes and costs.
We present \sys{}, a self-evolving memory management system that uses
these records to adapt later queries. The first challenge is attributing
reported use when an answer combines facts that can change over time.
A three-level architecture links raw conversations; first-order memory,
containing facts extracted for queries; and second-order memory, containing
records of their retrieval, reported use, and execution. Version identifiers
and links from computed results to supporting facts keep this attribution
consistent. The second challenge is deciding where more computation is
useful when queries require different facts and prior work can be reused.
Workload-aware memory queries adapt processing to the current request and
historical use records. Query-specific pipelines retrieve one fact, combine
independent facts, or resolve requests that depend on earlier results.
Cost-aware execution reuses verified results and chooses further acquisition
or verification by its predicted reduction in missing evidence and LLM-call
cost, updating its choices after each outcome.
Across eight long-term memory benchmarks, \sys{} matches or improves the
strongest evaluated prior system on each benchmark, with an average gain
of $2.6$ points. On \membench{}, it achieves higher accuracy with $50.7\%$
fewer memory-side LLM calls than a fixed three-call budget.
\end{abstract}
