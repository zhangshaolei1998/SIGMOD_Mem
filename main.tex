\begin{abstract}
LLM agents rely on persistent memory to retrieve information from past conversations. Existing memory systems primarily manage stored facts and optimize retrieval, but provide limited support for learning from previous memory query executions.
We present \sys{}, a self-evolving memory management system that continually updates stored information and improves query processing using historical execution feedback.
Realizing this design raises two technical challenges.
First, memory organization should capture not only stored facts but also how the system retrieves and uses them across queries.
\sys introduces a three-level memory architecture that organizes conversation history, extracted facts, and memory query history. It tracks fact versions and supporting evidence to maintain accurate memory-use attribution and provide reusable execution feedback.
Second, query processing should accommodate different evidence requirements while balancing retrieval effectiveness and execution cost. \sys combines query planning with cost-aware execution to handle single-fact retrieval, independent composition, and dependent composition. It exploits current evidence and historical execution feedback to reuse verified results and adapt execution efforts to queries.
Across eight long-term memory benchmarks, \sys matches or outperforms the strongest evaluated prior system on every benchmark, with an average gain of 2.6 points. On \membench{}, it achieves higher accuracy with 50.7\% fewer memory-side LLM calls than a fixed three-call budget.
\end{abstract}
