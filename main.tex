\begin{abstract}
Long-term LLM agents need memory that evolves in both what it stores and
how it uses stored evidence. Existing systems primarily retain user facts,
leaving the experience of memory use unrecorded, and commonly apply one
retrieval path to queries with different evidence requirements. We present
\sys{}, a continually evolving memory management system for LLM agents.
Its hierarchy retains raw User--Agent sessions, acquires source-backed
first-order facts on demand, and records second-order Agent--Memory
experience, including returned evidence, validated use, action outcomes,
and cost. For performance, normalized finite acyclic plans are partitioned
into single-fact retrieval, independent composition, and dependent
composition; each pipeline makes its coverage and binding obligations
explicit, while second-order experience guides grounding. For efficiency,
cost-aware execution combines current evidence gaps with historical action
outcomes to allocate a query-specific call budget and stop when further
work is not worthwhile. Across eight long-term memory benchmarks, \sys{}
matches or improves the strongest evaluated prior system on every benchmark
by $2.6$ points on average and, on \membench{}, reduces memory-side LLM
calls by $50.7\%$ while attaining higher accuracy.
\end{abstract}
