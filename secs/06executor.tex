\section{Cost-Aware Execution}
\label{sec:executor}

The pipeline fixes the result's evidence requirements. Execution selects
unresolved work and decides when to stop. A value can unlock a lookup;
a discovered event can add judgments; a completed check can make another
action redundant. \sys{} therefore reselects actions after each outcome,
using historical execution feedback to predict evidence benefit and cost.
Predicted mean cost ranks work; maximum reservations enforce the call
cap. Adaptive sampling varies inference effort across
questions~\cite{adaptiveconsistency,escsc}; here selection concerns the
remaining evidence checks.

\subsection{Estimating Evidence Benefit and Cost}
\label{subsec:new-budget}

An action is a bounded unit of evidence work: acquire a source-backed
property, verify a disputed value, resolve a plan block, or check its result.
Each pipeline supplies a finite set of bounded action templates. A
template identifies required inputs, the evidence checks it targets,
and its maximum call reservation. Instantiation uses the current query,
candidate population, and cached supports. Valid cached support removes
completed work; unresolved bindings identify prerequisites.
Let $\tau(q)$ be the executed action sequence, with $\tau_j(q)$ its
$j$th occurrence. In memory-side LLM calls,
\begin{equation}
\label{eq:cost}
C(q)=C_{\mathrm{plan}}(q)+\sum_{j=1}^{|\tau(q)|}c(\tau_j(q)).
\end{equation}
Every invocation is charged once, including repeated actions,
acquisition, verification, and semantic synthesis or validation by $g$.
Deterministic reads, selection, and arithmetic use zero LLM calls but
can incur latency. A call that reads memory and directly produces the
answer is charged once to $C(q)$ as result computation. Additional
agent-only query formulation and answer rendering are recorded separately.

\runin{Measuring evidence benefit}
The executor tracks the required checks for scope coverage, values,
versions, bindings, and results. A check is resolved by establishing its
required evidence against the current source snapshot. Deterministic
consequences of newly verified values, such as a comparison, are then
propagated through the plan.
For the current set of instantiated checks $\Omega$, let
$\ell(\Omega)$ be the unresolved fraction, with $\ell(\varnothing)=0$;
conflicts leave a check
unresolved. A validated plan and $\ell(\Omega)=0$ establish a supported
result; ambiguous compilation leaves a required check unresolved.

An action's observed reduction compares the same pre-action set:
$\Delta\ell(a)=\ell_{\mathrm{before}}(\Omega)-
\ell_{\mathrm{after}}(\Omega)$.
Newly discovered candidates add checks to the next decision's set.
Keeping the pre-action set fixed separates resolution of existing gaps
from discovery of additional work. The executor uses the expanded set
to determine support and select the next action.
A scan discovering the rain-altered outing can resolve coverage while
introducing an unknown setting. Measuring reduction on the original set
credits the completed coverage check; the next decision's expanded set
retains the new setting requirement.

\runin{Learning from comparable actions}
For each executed action, $\Uu$ stores its context, pre-action check set,
resolved checks, observed reduction, and actual call cost. The matching context contains action
kind, plan class, unresolved-check types, candidate count, dependency
depth, and cache availability (all, some, or none).

To estimate an available action's
evidence resolution $\widehat{\Delta\ell}(a)$ and cost $\widehat c(a)$,
the executor averages matched historical reductions and costs with one
declared prior observation. Detailed contexts match these fields exactly.
It backs off from the detailed context
to the same user's action-kind/plan-class history, then to the prior.
The same fields and backoff order apply to every action estimate.
Estimates are restricted to the template's currently unresolved checks:
benefit is zero if all its targets are supported and is bounded by their
unresolved fraction in $\Omega$. Cache availability, dependency depth,
and candidate count distinguish work within the same plan class.

A cold-start template supplies the initial reduction and call-cost
estimates. Its weight decreases as matched action records accumulate.
Each action declares an enforced maximum reservation $c_{\max}(a)$:
$0\leq c(a)\leq c_{\max}(a)$, distinct from its predicted mean cost.
An action that reaches its reservation returns its current evidence state.

\subsection{Adaptive Selection and Refinement}
\label{subsec:new-value}

\runin{Selecting ready work and its prerequisites}
A lookup with an unresolved input waits for its predecessor. A sequence
template lists a bounded set of prerequisite actions in dependency order,
with later inputs bound to earlier outputs. Instantiation removes work
already supported by cached facts and checks that the first remaining
action is ready. The sequence has its own matched context; its maximum
reservation covers all remaining action occurrences. Its observed gain
is the reduction on the common pre-sequence check set, so a check
resolved by several internal actions receives credit once.
If an internal action leaves the next binding unsupported, the sequence
returns its partial evidence and releases the remaining reservation.
For the longest-activity organizer, duration acquisition and comparison
can thus be priced together with the lookup they enable. The candidate
set contains instantiated ready actions and sequence templates; newly
discovered candidates trigger instantiation again.

First-order evidence identifies cache hits and unresolved checks;
memory query history supplies the matched reductions and costs.
From dependency-ready actions, the executor constructs a worklist
$\mathcal A_+(q)$ by scanning candidates in descending predicted net benefit
$\widehat{\Delta\ell}(a)-\lambda\widehat c(a)$.
A positive-benefit candidate is appended when its maximum reservation,
together with those already admitted, fits the remaining hard cap.
The maximum reservation, rather than the predicted mean, controls
admission: a cheap action on average can still require more calls than
the remaining budget permits.
The current additional-call budget is
\begin{equation}
\label{eq:new-adaptive-budget}
K(q)=\sum_{a\in\mathcal A_+(q)}c_{\max}(a)
\ \leq\ K_{\max}(q)-C_{\mathrm{spent}}(q).
\end{equation}
Here finite $K_{\max}(q)\geq0$ caps all memory-side calls, including planning, and
$C_{\mathrm{spent}}$ records calls already paid.
Planning is invoked only under a reservation that fits the cap; otherwise
the system stops with the plan unresolved.
$\lambda\geq0$ prices evidence resolution against calls.
The worklist and $K(q)$ are rebuilt after each action using the new
evidence state and spent cost. Newly discovered candidates and ready
lookups can therefore change both the selected work and its reservation.

When admissible actions exist, the next action maximizes predicted net benefit:
\begin{equation}
\label{eq:short}
\begin{aligned}
a^*&\in\argmax_{a\ \mathrm{admissible}}
 \{\widehat{\Delta\ell}(a)-\lambda\widehat c(a)\},\\
\mathrm{continue}&\ \Longleftrightarrow\
 \widehat{\Delta\ell}(a^*)>\lambda\widehat c(a^*).
\end{aligned}
\end{equation}
If no action is admissible, execution stops. Admissibility requires
available inputs and a reservation that fits the remaining cap.

Only the first selected candidate executes. The rebuilt worklist removes
completed checks and reusable prerequisites before re-estimation. For
example, acquiring a duration can settle the winner by comparison,
removing a separate winner-verification action; a conflicting duration
leaves verification available.

\runin{Updating the reservation and preserving reuse}
Only the selected action spends calls. Releasing its unused reservation
and rebuilding the worklist lets newly ready actions compete for the
remaining budget. Because actual cost is bounded by the admitted
reservation, each completed action leaves total spent cost within
$K_{\max}(q)$. The same test applies to a prerequisite sequence, including
all of its internal calls.

Deterministic work is not repeated on unchanged inputs; semantic retries
consume the finite cap. With a finite plan and snapshot, execution
terminates. Disagreement can trigger verification, while unsupported
evidence requires acquisition. An input change invalidates only its
dependent descendants. On stopping, unresolved checks retain partial or
unknown $\sigma$; they cannot become supported through budget exhaustion.

\begin{memoryexample}{Example 3: reuse and selective acquisition}
\textbf{Warm query.} Alice again compares the outdoor activities.
Reuse verified settings and durations: $4>3$, with $K(q)=0$ additional
memory-side calls. Agent answer generation is separate.

\smallskip
\textbf{New gap.} A closed March 23 session says,
\emph{We planned an outdoor picnic, but rain changed our plans.}
Its follow-up says, \emph{We ate inside River Cafe instead.}
The two descriptions refer to the same outing.
Alice's March 24 count needs its actual occurrence and setting,
not merely the planned picnic.

\smallskip
\textbf{Selective action.} Verify the outing and acquire its actual setting when
predicted benefit exceeds cost, charging extraction/verification calls.
Reuse the three earlier judgments; update only the new outing:
$1+0+1+0=2$.

\smallskip
\textbf{Unavailable evidence.} Without the follow-up, the closed
four-candidate scope supports $[2,3]$, not an exact count.
Repeating the planned-picnic fragment cannot resolve this gap.
\end{memoryexample}

$\Uu$ stores $C(q)$, action outcomes, and evidence resolution independently
of use reports. Validated reported use updates fact priorities
(Section~\ref{subsec:new-experience}).
