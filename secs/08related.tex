\section{Related Work}
\label{sec:related}

\runin{Memory management systems}
Memory systems manage context tiers, conversational facts, temporal
relations, and linked notes~\cite{memgpt,mem0,zep,agenticmem}.
MemoryBank models forgetting~\cite{memorybank}; Generative Agents
synthesize reflections~\cite{generativeagents}.
VikingMem introduces event/entity abstractions, event-driven entity
updates, timeline compression, and time-weighted
retrieval~\cite{vikingmem}. Tool-call and failure
histories update tool entities with experience for future
invocations~\cite{vikingmem}.
MemLens organizes atomic units and summaries in a provenance-linked
tree. Shapley-style marginal contributions guide retention and
reranking~\cite{memlens}.

\sys{} addresses the management of observed agent--memory interactions.
Its second-order records associate returned and reported-use fact
versions with derivations, action outcomes, and costs. This state guides
both access and execution (Table~\ref{tbl:positioning}).

\runin{Learning from memory interactions}
RMM uses memory citations to update a reranker~\cite{rmm}; MemRL
learns episodic utilities from rewards~\cite{memrl}; Live-Evo updates
experience weights and guidelines~\cite{liveevo}. MemSkill learns a
selection policy over memory-construction skills and revises those
skills using difficult cases~\cite{memskill}; UMEM jointly optimizes
extraction and memory updates using query-neighborhood utility~\cite{umem}.
\sys{} validates reported evidence references for version-specific credit,
including facts supporting a derived result. Missing reports leave use
unobserved; execution outcomes still update cost estimates. Source
checks determine support; feedback guides later access and execution.

\runin{Memory queries and adaptive execution}
HippoRAG retrieves over a knowledge graph~\cite{hipporag}; MemoRAG uses
global memory to generate retrieval clues~\cite{memorag}.
LongMemEval separates indexing, retrieval, and
reading~\cite{longmemeval}. MemR$^3$ controls retrieval, reflection, and
answering through an evidence-gap tracker~\cite{memr3}.
LOTUS optimizes semantic operators~\cite{lotus}; DocETL rewrites
document pipelines~\cite{docetl}; EVAPORATE and QUEST optimize
extraction work~\cite{evaporate,quest}.
Our pipelines expose coverage and binding requirements; interaction
history guides the evidence work remaining within them.

Eddies adapts operator routing~\cite{eddies}, and Bao learns optimizer
hints from execution feedback~\cite{bao}. Here actions acquire or verify
conversational evidence, and their outcomes change the next decision.
Self-consistency aggregates sampled
answers~\cite{sc}; Adaptive-Consistency and ESC stop from answer
agreement~\cite{adaptiveconsistency,escsc}. Our rule prices evidence
resolution against cost and preserves verified subresults across queries.

\section{Conclusion}
\label{sec:conclusion}

\sys{} links raw sessions, source-backed facts, and agent--memory
experience in a self-evolving memory management system. Fact versions
and derivations connect reported use to reusable evidence.
Workload-aware queries enforce coverage and dependencies; cost-aware
execution reuses verified results and selects remaining work using
historical outcomes and costs. Across eight benchmarks, it improves the
strongest evaluated prior system by $2.6$ points on average. On
\membench{}, it achieves higher accuracy with $50.7\%$ fewer memory-side
LLM calls than a fixed three-call budget.
