\section{Preliminaries}
\label{sec:preliminary}

\label{subsec:new-interface}

The user exchanges a \emph{question} $Q$ and an \emph{answer} $A$ with
the agent. The agent exchanges a \emph{memory query} $q$ and
\emph{retrieved memory} $m$ with the memory system:
\begin{equation}
\label{eq:new-interface}
\mathrm{User}\xrightarrow{Q}\mathrm{Agent}
\xrightarrow{q}\Mm\xrightarrow{m}\mathrm{Agent}
\xrightarrow{A}\mathrm{User}.
\end{equation}
A question can induce several memory queries; its conversation history
and each query's second-order experience are recorded separately.
The agent uses $m$ to generate $A$. The memory support guarantee applies
to $m$; claims the agent adds to $A$ require separate justification.
The query/evidence
terminology is consistent with memory retrieval work~\cite{mem0,memr3}.

A memory query specifies an information need, an entity or population
scope, and a temporal scope. Execution uses the source snapshot available
when $q$ arrives; newly closed sessions become available to later queries.
Current and historical questions can therefore select different
versions of the same fact. We model finite requests for facts or
computations over the recorded user history and evaluate them against
the source snapshot fixed at query arrival.

Retrieved memory is $m=(v,E,\sigma)$,
where $v$ is a value, fact collection, justified partial bound, or
$\bot$ when no value can be established.
$E$ is a finite evidence bundle of source-backed fact versions and
scope, version, and binding checks, including unresolved checks.
$\sigma$ is
\texttt{supported}, \texttt{partial}, or \texttt{unknown}. A count needs
evidence that covers its requested population; a dependent result needs
evidence for each required link. Supported means all required checks
are discharged; partial means some evidence is established but an
obligation remains; unknown means no source support for the result is established.
A verified empty scope establishes supported absence. An unresolved
check leaves its predicate unknown.
These states are defined by the evidence obligations of a validated
plan against its source snapshot.

Experience is retained per user: later queries can benefit from earlier
fact use and execution outcomes without mixing different users' states.
Table~\ref{tab:new-notation} lists the core symbols; each operational
quantity is defined where it is used.
