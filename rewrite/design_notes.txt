一、全篇主线
Question Q -> Agent -> Memory Query q -> Memory -> Retrieved Memory m
-> Agent -> Answer A -> User。
返回 m=(结果 v，支撑事实 E，支持状态 sigma)，再记录 Agent 实际采用了哪些事实。
一次 Question 可以触发多个 Query。原始会话在 session 结束时写入 H。
所有 Agent 自己生成的内容保留说话者身份；建议或推测不能自动当作用户事实。

持久状态只有三类：M=(H,F,U)。
H：原始会话，保留尚未被任何查询需要的证据。
F：一阶事实，Query 暴露信息需求后按需提取、验证、规范化并保存。
U：二阶使用经验，保存一阶事实被检索、被采用、支持检查与执行成本的经验。
F 让 Agent 更了解用户；U 让 Memory 更了解这个用户的信息需求与服务代价。

三、为什么不再用 POINT / AGGREGATE / COMPARE
原三类按表面任务列举，比较与聚合重叠，多跳关系没有清晰位置。
新三类按证据请求的依赖结构定义 P=(R,D,g)：
Direct：没有回答依赖且为原子的单事实请求，直接返回所需值。
Parallel：没有回答依赖但非原子，独立取得候选证据再计数、比较、排序或汇总。
Dependent：一个信息目标的输出绑定后续请求的实体、属性或时间，即 D 非空。
分类按 D 空 / 非空，再按 atomic / non-atomic 划分，互斥且覆盖有限无环计划。
完整计划允许递归嵌套，各子请求也遵循同一划分。
“最长户外活动的组织者”是 Dependent：先 Parallel 选活动，再 Direct 取组织者。
人口展开及其归约视为一个聚合操作，不把此内部顺序误作信息目标间的依赖。
不能把这个命题扩张成“任意自然语言都必然被正确分类/回答”。

四、二阶 Memory 的技术变化
从 session popularity 改成 fact 的上下文使用经验。
分别记录 exposed/retrieved 和 actually used；使用率有先验平滑。
Agent 报告使用且有来源支持的事实每个 query 计一次 use；确定性计算的支撑事实同理。
保证 0 <= n_used <= n_retrieved；缺失 use report 不计 use，不引入额外的连续 credit 参数。
计数中的否定候选同样是支撑，不能只从最终 Answer 文本反推使用。
无法取得 use report 时，只计 exposure，不能把所有召回项视为 useful。
grounding 用当前相关性乘上下文使用率排序，并保留新事实探索。
完整人口集合不能仅保留热门 top-k；预算不足时返回 partial。
不声称经常采用等价于正确，不声称无偏，不声称随 query position 必然变好。
上下文和执行统计需要单独索引；若保留全部 trace，空间会随工作负载增长。
若后续想写有限空间界，必须先给定上下文数和 trace 保留策略。

五、动态成本执行
不设置 K_Direct=1、K_Parallel=3 这类常量。
K(q) 根据当前缺口、候选数量、依赖深度、冲突、已有事实和 U 中历史成本/效果估计。
目标是预测证据风险 + lambda * 成本，在资源上限以内决定执行轮数。
每轮后比较进一步执行的预计风险改善与代价，只重执行不确定块。
有关联的多步行动要作为 action bundle 评估，避免单步收益为零就过早退出。
已验证的算术可以不额外采样；证据仍有歧义的直接检索也可能需要更多工作。
成本完整记入 planning / acquisition / verification / execution。
Agent 最终 Answer 的生成成本另外计入 end-to-end 指标。
source-grounding/coverage 诊断是可观察代理，不能冒充线上 gold correctness。
agreement 只比较规范化值，而且不能修复共享错误事实；必要时重新读原始来源。
停止规则证明只适用于条件期望准确时的局部 risk+cost 目标，不宣称全局最优。
